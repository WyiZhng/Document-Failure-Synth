# 带 link_to 源数据输入支持设计

## 1. 背景

当前合成流水线把非空 link_to 视为不支持的输入：

- src/synth/material.py 的输入检查会直接抛出异常；
- 素材抽取只遍历 children，不会把只存在于 link_to 中的目标子树纳入素材；
- src/synth/gt_builder.py 重建结果时固定写入 link: false 和 link_to: []。

因此，带有跨页图片、表格或其他引用目标的合法样本会在 LLM、分页和 GT 阶段之前被丢弃。

当前 data/source 中已经有两个具有代表性的样本：

- task_001_015_raw：第 4 页正文节点引用第 6 页的图标题和图片；三个锚点指向同一个目标 p5-b5。
- task_001_017_raw：第 1 页正文中的“如下表”引用第 2 页的表格；目标根 p1-fake1 是虚拟节点，真实表格位于其子节点 p1-b1。

## 2. 已确认的产品决策

1. 保留 link/link_to 关系，并渲染目标子树内容。
2. 目标按照原始 page_index 和 bbox 渲染，不复制到锚点附近，不移动原始位置。
3. 同一目标按节点 id 去重，只渲染一次，但保留所有锚点到该目标的关系。
4. 目标子树中的文字节点按普通节点生成英文；图片保留原图；表格保留结构和内容；虚拟包装节点不单独渲染。
5. 处理整份源文档的全部页面，不再默认截断为前 5 页。配置使用 max_source_pages: null 表示全量页面。

## 3. 设计目标与非目标

### 目标

- 合法的带 link_to 样本能够进入现有双语合成流程。
- 跨页目标、虚拟目标和多个锚点共享目标都能正确处理。
- 目标内容只出现一次，引用关系在最终 GT 中仍可被 Trainer 消费。
- 无 link_to 样本的现有输出行为保持不变。

### 非目标

- 不重新推断原始文档的引用语义；只消费已有的 link/link_to。
- 不把引用关系改造成普通 children 父子关系。
- 不在锚点处复制图片、表格或其他目标内容。
- 不改变现有翻译提示词和双栏分页规则之外的版面策略。

## 4. 核心架构：节点池与关系图分离

在 material.py 中增加输入规范化阶段，把原始树拆成四个相互关联的结果：

    primary_tree       原始 children 结构，保留阅读顺序
    nodes_by_id        主树节点和 link_to 目标的规范节点索引
    relations          anchor_id -> target_id 的引用关系
    render_blocks      去重后的真实可渲染节点

### 4.1 节点索引

- 主 children 树和 link_to 目标递归加入 nodes_by_id。
- 节点以逻辑 id 去重；具体 member ID 也必须去重，因为它们是实际版面块的身份。
- 同一个节点同时存在于主树和 link_to 时，主树版本优先提供版面位置；目标快照只补充主树缺失的子节点。
- 目标快照中的根节点即使是虚拟节点，也要保留在节点索引和关系图中，因为下游需要知道引用的目标根。

### 4.2 关系集合

每个非空 link_to 项生成一条关系：

    anchor_id = 当前节点 id
    target_id = link_to 目标根 id

同一个 target_id 被多个锚点引用是合法情况，不合并锚点关系。

### 4.3 可渲染块

- 非虚拟节点的 member 生成普通 SourceBlock。
- 虚拟节点不生成自己的 SourceBlock，但递归处理其真实子节点。
- 只出现在 link_to 中的目标，其真实子节点也进入 render_blocks。
- 已经通过主树加入的目标不重复加入。
- 目标的版面顺序优先使用主树顺序；对于脱离主树的目标，按目标页及其第一个真实子节点的坐标插入该页。

## 5. 流水线数据流

### 5.1 全量页面读取

load_material 读取 images_path 下的全部 raw-page-N.png，并将 max_source_pages: null 解释为源文档总页数。页码继续使用 0-based page_index。

如果节点引用的页面没有对应图片，应在素材阶段报告输入错误，而不是让后续 HTML 或 LLM 阶段失败。

### 5.2 HTML、翻译与分页

规范化后的 render_blocks 继续进入现有流程：

    render_blocks
        -> build_source_html
        -> rewrite_html
        -> paginate
        -> render

这些阶段不需要理解 link_to 的图语义：

- 文字、标题节点：按现有标记和翻译规则生成中文/英文配对；
- 图片：保留图片块；
- 表格：保留表格结构和源内容；
- 虚拟节点：不产生独立 HTML 块。

由于目标已经在 render_blocks 中去重，分页器不会因为多个引用而重复排版目标。

### 5.3 校验

现有块级校验继续比较渲染后的中文块与规范化后的 render_blocks。另外增加关系校验：

- 每个关系锚点存在于规范节点索引；
- 每个关系目标存在于规范节点索引；
- 每个非虚拟目标的真实成员都有且只有一个渲染放置结果；
- 虚拟目标至少包含一个可解析的真实后代；
- 目标页超出原先 5 页时仍有对应渲染结果；
- 输出没有重复的可渲染节点 ID。

### 5.4 GT 重建与 ID 映射

分页后，渲染块会从源 member ID 映射为新的输出块 ID。GT 构建需要使用同一份映射重建主树和关系目标：

1. 为每个源 member 建立源 ID 到中文/英文输出 ID 的映射。
2. 主树节点按现有逻辑重建，但锚点节点保留 link: true。
3. 使用规范节点缓存重建每个 link_to 目标，避免为同一目标生成不一致的副本。
4. 虚拟目标生成稳定的虚拟输出包装节点，其真实子节点使用已映射的输出 ID。
5. 已经在主树中出现的目标，在 link_to 中引用其重建快照；只存在于关系中的目标，仍通过 link_to 保存其重建子树。
6. 不在最终输出中保留失效的源 ID，也不把所有关系清空。

因此，输出同时满足两件事：目标在 label.json 和页面中有真实位置，关系在 multi-page-final.json 中仍可追溯。

## 6. 错误处理

以下是确定性的输入契约错误，应在素材规范化阶段直接报告，并避免重复调用 LLM：

- link_to 项缺少目标 id；
- link: true 但 link_to 为空；
- 虚拟目标没有任何真实子节点；
- 目标节点和所有后代都没有可渲染内容；
- 节点 ID 在主树与目标快照中存在页码、类别、成员或坐标冲突；
- 引用页面没有源图片；
- 关系递归形成循环。

错误信息至少包含样本目录、锚点 ID、目标 ID 和失败原因。LLM 翻译失败、浏览器渲染失败等运行时错误仍沿用现有重试机制。

## 7. 测试与验收

### 单元测试

- 主树节点和 link_to 目标按 ID 去重；
- 三个锚点引用同一目标时只产生一份渲染块；
- 虚拟目标只渲染真实后代；
- 目标只存在于 link_to 时仍进入素材池；
- 跨页目标按自己的页面和坐标渲染；
- 节点冲突、缺失目标、缺失图片和循环关系给出明确错误；
- GT 中源 ID 到输出 ID 的关系映射正确。

### 真实样本集成测试

#### task_001_015_raw

- 识别 3 条引用关系；
- 唯一目标为 p5-b5；
- p5-b5 及其图片子节点在第 6 页只渲染一次；
- 输出保留三个锚点到同一目标的关系。

#### task_001_017_raw

- 识别第 1 页正文到第 2 页表格的关系；
- p1-fake1 不产生独立渲染块；
- p1-b1 表格渲染一次；
- 输出保留正文到表格目标的关系。

#### 无链接基线

task_001_016_raw 和 task_001_037_raw 的节点顺序、类别、块数量和 GT 结构保持现有行为。

### 下游验收

将生成的 multi-page-final.json 交给 Trainer 的阶段 0/引用关系处理流程，验证：

- 同页关系可被解析；
- 跨页关系进入长距离目标处理；
- reference_link 样本仍能生成；
- 目标文字、表格和图片没有在转换过程中丢失。

### 可观测性

每个样本记录以下计数，便于区分输入问题和后续处理问题：

    link_count
    unique_target_count
    materialized_target_block_count
    virtual_target_count
    unresolved_link_count

## 8. 完成标准

设计实现完成后，以下条件必须同时满足：

    带 link_to 的合法样本不再被预检查直接丢弃
    目标内容按原始位置完整渲染且不重复
    最终 GT 保留 link/link_to 关系
    无 link_to 样本行为不回归
    Trainer 能继续消费生成结果
